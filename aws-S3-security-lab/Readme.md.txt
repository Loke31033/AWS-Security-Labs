# Project 2 — AWS S3 Security Monitoring & Incident Response Lab

## Overview

This project demonstrates an end-to-end AWS cloud security workflow
for securing, monitoring, detecting, investigating, and remediating
security issues in an Amazon S3 environment.

The lab uses an intentionally controlled S3 misconfiguration to
simulate a real-world cloud security scenario.

The complete workflow was performed using AWS-native security services.

---

## Objective

Build a secure and monitored Amazon S3 environment and demonstrate
the ability to:

- Identify S3 security risks
- Configure preventive security controls
- Detect security-sensitive API activity
- Investigate CloudTrail events
- Build automated EventBridge detection
- Store detection evidence in CloudWatch Logs
- Remediate the security issue
- Validate the final security state
- Document the incident professionally

Controlled Security Scenario

A controlled S3 security misconfiguration was introduced
to simulate potential public data exposure.

The test configuration included:

Principal: *
Action: s3:GetObject

The scenario was performed only against the lab bucket.

No production or sensitive data was used.

Remediation

After completing the controlled detection exercise,
the insecure configuration was remediated.

Actions performed:

Removed the intentionally created public bucket policy.
Enabled S3 Block Public Access.
Verified S3 encryption.
Verified S3 Versioning.
Re-checked IAM Access Analyzer.
Verified CloudTrail monitoring.
Verified EventBridge detection.
Verified CloudWatch Logs evidence.

Key Security Lessons
1. Preventive controls are not enough

A secure cloud environment needs both:

Preventive Controls
        +
Detective Controls
        +
Investigation
        +
Response
2. CloudTrail provides audit visibility

CloudTrail allows security analysts to investigate AWS API
activity and understand what happened in the environment.

3. EventBridge enables automated detection

EventBridge can identify specific security-sensitive events
from AWS service activity and route them to appropriate targets.

4. IAM Access Analyzer helps identify unintended access

Access Analyzer can help identify external access paths
that may create security exposure.

5. Remediation must be validated

A security issue is not considered fully resolved simply
because a configuration was changed.

The final security state must be verified.
