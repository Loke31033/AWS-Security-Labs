# Lessons Learned

## 1. Root Account Security

The AWS root account has extremely powerful permissions and should not be used for normal daily operations.

MFA was enabled on the root account as an additional security control.

---

## 2. IAM Users

IAM users represent identities that can interact with AWS resources.

For practical environments, permissions should be carefully controlled instead of giving users unrestricted access.

---

## 3. IAM Groups

Users with similar responsibilities can be placed into groups.

Example:

```text
cloudsec-analyst
        |
        v
CloudSecurity-Analysts


ermissions can then be managed at the group level.

This makes access management easier and more consistent.

4. IAM Policies

IAM policies define what actions an identity can perform on AWS resources.

A policy generally contains:

Effect
Action
Resource

Example:

Effect   → Allow
Action   → iam:List*
Resource → *
5. Least Privilege

The most important lesson from this project was the principle of least privilege.

Instead of:

Administrator
     |
     v
Everything

the analyst should receive only:

Required permissions
       |
       v
Read-only IAM access
6. Permission Testing

Permissions should not simply be assumed to work correctly.

The IAM Policy Simulator can be used to test whether an identity would be allowed or denied for specific actions.

Example:

iam:ListUsers
       |
       v
Allowed

while:

iam:CreateUser
       |
       v
Denied
7. Excessive Permissions

The controlled misconfiguration demonstrated that adding a single additional permission can change the security posture of an identity.

Before:

iam:CreateUser → Denied

After excessive permission:

iam:CreateUser → Allowed

Therefore, IAM permissions should be regularly reviewed.

8. Security Remediation

Finding a security problem is only part of the job.

A security analyst should:

Identify
   ↓
Understand
   ↓
Assess Risk
   ↓
Remediate
   ↓
Retest

In this project, removing the excessive policy restored the intended security configuration.

9. MFA

MFA provides an additional authentication factor.

The project demonstrated that sensitive identities should have stronger authentication controls.

10. IAM Access Analyzer

IAM Access Analyzer can help identify unintended external access to resources.

It provides another layer of visibility beyond manually reviewing IAM policies.

11. Security Mindset

The biggest lesson from this project is:

Security is not simply configuring a service. Security means continuously asking whether access is necessary, whether the configuration creates risk, and whether the controls actually work.
